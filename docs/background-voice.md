# Фоновая станция и экран блокировки (0.8.0)

Один раз открыть приложение, дать доступ к микрофону и через кнопку
«Настройки фоновой работы» включить оба пункта:

1. «Поверх других приложений» — разрешение Android для открытия Activity из фона.
2. «Без экономии батареи» — исключение только для этого приложения.
3. Необязательно: «Команда отбой» — системное разрешение Device Admin только
   для force-lock, чтобы немедленно погасить/заблокировать экран. Подтверждается
   пользователем; нет wipe-data, управления паролями, device-owner provisioning.

«Отбой» распознаётся Vosk только внутри окна команды после обращения,
как отдельная финальная фраза. С 0.8.0 после команды цвета Vosk ещё доступен
до 6 секунд без обновления текста: «отбой» в этом окне не требует нового wake.
После окончания окна снова нужно обращение. Круг показывает время до гашения
voice-opened экрана, новое распознанное слово перезапускает отсчёт.
lockNow не выключает службу/CPU wake lock. При следующей разблокировке Android
может потребовать PIN/пароль; этот механизм не эквивалентен просто чёрному фону.

С 0.7.2 экран по wake открывается после трёх последовательных оценок ≥ 0.65,
не по единственному пику. При падении score серия обнуляется; после команды
сброс вместе с детектором. Это задерживает подтверждение на ~160 мс, но не
защищает от длительного ложного сигнала. Для него всё ещё нужны новые negative
данные/проверка модели. Не считать старую минутную validation длительным тестом.

Foreground-служба с тихим постоянным уведомлением продолжает работу после
Home и закрытия Activity. START_STICKY позволяет системе восстановить службу,
но не гарантирует бессмертие процесса. CPU удерживается partial wake lock
с таймаутом 10 минут, продлеваемым каждые 5; при остановке освобождается.
Это увеличивает энергопотребление; исключение батареи не заменяет soak-test.

По wake при разрешённом overlay открывается обычная Activity (overlay-окно
не рисуется). showWhenLocked/turnScreenOn показывают её над keyguard и будят
экран. PIN/пароль/биометрия не отключаются, requestDismissKeyguard не вызывается.
При отсутствии разрешения слушание продолжается, окно можно открыть уведомлением.
После триггера Vosk получает только следующие кадры; старый pre-roll не возвращён.

После перезагрузки приходит тихое уведомление «Запустить помощника»:
нужно нажать его один раз. Boot receiver не запускает микрофон. Если ранее
было нажато «Остановить», boot-напоминание не создаётся. Force-stop, запрет
микрофона или OEM-выгрузка могут остановить работу; скрытый обход не реализуется.

## Проверка на LG

0. После открытия по обращению ничего не говорить: примерно через 6 с экран
   должен погаснуть. Сказать цвет: круг должен начать отсчёт от последнего
   обновления распознанного текста и погасить экран после 6 с тишины. Одинаковые
   repeated partial не должны удерживать его. Переход в другое приложение
   отменяет право гасить экран старым timer; это не включает глобальную блокировку.
   Запуск Activity через иконку сам по себе автоотбой не включает. При отсутствии
   force-lock admin Android не позволит мгновенную блокировку.

1. После выдачи разрешений вернуться в приложение и выполнить
   `scripts/verify-wakeword-runtime.ps1 -ExpectedProfile personal-v2 -RequireBackgroundPermissions`.
2. Нажать Home/открыть другое приложение, произнести обращение; проверить
   открытие станции, затем цвет. Команды без обращения не должны выполняться.
3. Заблокировать телефон и погасить экран. Проверить, что обращение показывает
   станцию, а защищённые приложения по-прежнему требуют разблокировки.
4. Проверить микрофон через 10–30 минут и несколько часов, память/нагрев/заряд.
   USB/зарядка и настоящий idle без зарядки — разные условия; short check не soak-test.
5. Перезагрузку и boot-напоминание проверять отдельно, с учётом работающего HA;
   автоматическая перезагрузка телефона в этой задаче не выполняется.
