# План установки

Этот план подготовлен, но **не запущен**. Любые действия на телефоне начинаются
только после отдельного подтверждения пользователя.

## Этап 0. Уже выполнено

- Установлены локальные Android Platform Tools и подписанный LG Mobile Driver.
- ADB авторизован; уникальные идентификаторы не сохраняются.
- Собран базовый отчёт состояния устройства.
- Подтверждено отсутствие root и несовместимость штатного ядра с Docker.
- Исследованы варианты A–D; выбран обратимый не-root POC.

## Этап 1. Подготовить доверенные APK

1. Зафиксировать точные URL и версии Termux и Termux:Boot из одного доверенного
   канала: F-Droid либо официальные GitHub Releases.
2. Скачать APK на ноутбук, сохранить SHA-256 и сведения о подписи/источнике.
3. Не устанавливать APK автоматически, пока пользователь не подтвердит
   источник и контрольные суммы.
4. После подтверждения установить приложения через пользовательский интерфейс
   или `adb install`; записать команды и результаты в журнал.

Статус: этап выполнен. Проверенный набор зафиксирован в
`docs/termux-apk-manifest.md`; установлены Termux 0.118.3 и Termux:Boot 0.8.1.
Откат описан в `docs/rollback.md`.

## Этап 2. Минимальная настройка Android

1. Один раз открыть Termux и Termux:Boot.
2. Проверить версию Android/Termux и доступное место.
3. Запросить у пользователя отдельное согласие на исключение Termux из
   оптимизации батареи — это изменение настройки телефона.
4. Не отключать глобально phantom process monitor на этом этапе.
5. Не устанавливать Magisk, не изменять boot и не прошивать разделы.

## Этап 3. Воспроизводимый bootstrap

Подготовить один идемпотентный сценарий, который:

1. обновляет пакеты Termux;
2. устанавливает `proot-distro`, диагностические утилиты и при необходимости
   `mosquitto`;
3. разворачивает зафиксированный официальный Ubuntu 26.04 ARM64 rootfs;
4. создаёт отдельного непривилегированного пользователя и каталог данных;
5. устанавливает совместимую версию Python и Home Assistant в `venv`;
6. создаёт start/stop/healthcheck-скрипты и сценарий Termux:Boot;
7. сохраняет версии, хеши, команды и коды завершения в локальный журнал;
8. не содержит паролей, токенов, серийного номера или других секретов.

Если установка зависимостей Core под Android/PRoot не воспроизводится, запасной
POC — запуск распакованного ARM64 userspace официального HA-образа через
совместимый PRoot/udocker-механизм. Это также не считается Docker и принимается
только после измерения idle CPU.

Статус: Termux bootstrap, Ubuntu 26.04 PRoot и Home Assistant Core 2026.10.1
установлены воспроизводимыми сценариями. Следующий шаг — первый запуск и
функциональная проверка до настройки автозапуска.

## Этап 4. Проверка функций

1. Запустить чистый Home Assistant и открыть интерфейс из LAN.
2. Убедиться, что сервис недоступен извне локальной сети.
3. Проверить WiZ: сначала discovery, затем ручной IP при необходимости.
4. При необходимости запустить Mosquitto отдельно и проверить MQTT 5.
5. Matter и USB-координаторы не включать в первый POC.
6. ESPHome собирать/прошивать с ноутбука; OTA проверить позднее.

## Этап 5. Надёжность

- 72 часа работы с выключенным экраном.
- Перезагрузка телефона и автоматический старт.
- Потеря/возврат Wi-Fi и DHCP lease.
- Контроль температуры, зарядки, RAM, swap, диска и idle CPU.
- Проверка, что Android не убил Termux/PRoot и что Home Assistant отвечает.
- Проверка целостности данных после принудительной остановки процесса.

## Условия остановки

POC останавливается без дальнейшего вмешательства, если наблюдаются постоянная
высокая нагрузка, перегрев, быстрый износ батареи, частое уничтожение процессов
Android, невоспроизводимые Python-зависимости или потеря данных.

Root/chroot, изменение глобальных Android settings, Magisk, кастомное ядро и
перепрошивка рассматриваются только в новом этапе с резервным планом и
отдельным явным согласием.
