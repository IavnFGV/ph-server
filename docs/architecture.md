# Варианты архитектуры

Дата оценки: 2026-10-15. Устройство: LG V50S ThinQ LM-V510N (`mh2lm`), Android
12, ядро 4.14.190, загрузчик уже сообщает состояние `unlocked`, root отсутствует.

## Краткий вывод

Для текущей цели рекомендуется **вариант C: не-root proof of concept через
Termux и PRoot**, без прошивки и изменения ядра. Он позволит проверить сам
подход, локальный интерфейс Home Assistant, WiZ и MQTT, но не должен считаться
поддерживаемым или гарантированно надёжным 24/7-сервером.

Для действительно надёжной домашней автоматизации правильный итоговый хост —
отдельное устройство, поддерживающее Home Assistant OS либо стандартный
Home Assistant Container. Телефон можно сохранить как исследовательскую
платформу или резервный экспериментальный узел.

## Матрица вариантов

| Вариант | Root | Прошивка/ядро | Docker | Оценка | Решение |
|---|---:|---:|---:|---|---|
| A. Android + root + chroot + Docker | Да | Кастомное ядро | Только после модификации ядра | Высокий риск, тяжёлое сопровождение | Отклонить |
| B. Android + root + Debian chroot, без Docker | Да | Патч boot/Magisk | Нет | Технически реалистичнее, но Core не поддерживается | Возможный поздний эксперимент |

## A. Root, Linux chroot и Docker

Этот путь не проходит проверку штатного ядра. На телефоне отсутствует часть
обязательных namespaces, cgroup-контроллеров и OverlayFS. Root не добавляет
функции ядра, поэтому Magisk сам по себе проблему не решит.

Чтобы получить Docker, пришлось бы собрать, установить и сопровождать кастомное
ядро, проверить сеть, firewall, cgroups, storage driver и совместимость с
Android userspace. Это резко повышает риск bootloop/потери данных и не
соответствует текущему условию минимальной инвазивности.

Решение: отклонить.

## B. Root и Debian chroot без Docker

Настоящий chroot использует штатное ядро напрямую и работает быстрее PRoot.
Внутри можно запускать Home Assistant Core и Mosquitto как обычные процессы,
не требующие контейнерных namespaces. Однако потребуются root/Magisk и
модификация boot-образа, а Home Assistant Core больше не является официально
поддерживаемым методом установки.

Этот вариант имеет смысл только после успешного POC, если пользователь
осознанно примет риски root. Он не требует перепрошивки Android целиком, но
требует резервного boot-образа, проверенного способа восстановления и отдельного
согласования каждого изменения.

Решение: оставить как второй этап, сейчас не выполнять.

## C. Termux и PRoot без root

Преимущества: не нужен root, не меняются boot/system/vendor, можно удалить
окружение как обычные приложения и файлы. Debian/Ubuntu userspace через PRoot
даёт привычную glibc-среду для Python-зависимостей Home Assistant. Mosquitto
лучше запускать отдельным нативным пакетом Termux.

Ограничения:

- это не Docker и не официально поддерживаемый Home Assistant Container;
- PRoot добавляет CPU/I/O overhead и не предоставляет systemd/cgroups;
- Android 12 может останавливать фоновые и ресурсоёмкие процессы;
- потребуются исключение из оптимизации батареи, wake lock и Termux:Boot;
- обновления Home Assistant/Python могут ломать зависимости;
- часть сетевого обнаружения следует проверять практически на Wi-Fi телефона.

Решение: использовать только как измеримый POC. Критерии успеха — стабильная
работа 72 часа с выключенным экраном, восстановление после перезагрузки и
переподключения Wi-Fi, приемлемые температура/расход батареи, WiZ и MQTT.

## D. Нативный Linux

Для семейства `lg-mh2lm` есть следы экспериментальной mainline/postmarketOS-
работы: порт загружался, а для LG G8X отмечены Wi-Fi, Bluetooth и thermal.
Однако в текущем официальном `pmaports` готового пакета `mh2lm` нет, точный
вариант LM-V510N не подтверждён, а критичные для сервера UFS, зарядка,
suspend/resume, watchdog, USB и reboot не проверены как законченный набор.
Наличие экспериментальных UEFI/Windows on ARM разработок также не означает
готовность Linux-сервера и требует высокорисковых изменений разделов.

Решение: отклонить до появления поддерживаемого порта точной модели.

## Компоненты рекомендуемого POC

- Android остаётся штатным.
- Termux из F-Droid или официального GitHub, не экспериментальная Play-сборка.
- Termux:Boot для восстановления процессов после загрузки.
- PRoot-Distro 5.10 с Ubuntu 26.04 LTS для Home Assistant Core. Ubuntu выбран
  вместо первоначально планировавшегося Debian Bookworm, потому что актуальному
  Home Assistant нужен Python >=3.14.2, а Ubuntu 26.04 предоставляет Python 3.14
  для ARM64.
- Mosquitto как отдельный пакет Termux, только если нужен MQTT.
- Home Assistant доступен только из локальной сети; проброс портов наружу не
  выполняется.
- ESPHome-компиляция и первичная USB-прошивка остаются на ноутбуке до отдельной
  проверки ресурсов и USB OTG.

## Ответы на ключевые вопросы

- **Нужен ли root сейчас?** Нет.
- **Запустится ли стандартный Docker после получения root?** Нет, не на
  обнаруженной конфигурации штатного ядра.
- **Нужно ли модифицировать ядро?** Только если принципиально нужен Docker; для
  рекомендуемого POC — нет.
- **Можно ли запустить Home Assistant без перепрошивки?** Да, экспериментально
  через Termux/PRoot, но это неподдерживаемый вариант.
- **Можно ли считать телефон готовым production-сервером?** Нет. Сначала нужен
  POC и soak-тест; даже после них ограничения поддержки и Android останутся.
