# LG V50S: домашний сервер и голосовая станция

Практический эксперимент: превратить LG V50S ThinQ (`LM-V510N`, `mh2lm`) в
локальный узел Home Assistant и голосовую станцию, не начиная с прошивки, root
или необратимых изменений. Все проверки, неудачные попытки и причины смены
архитектуры сохраняются, чтобы проект можно было повторить или откатить.

## Где проект находится сейчас

- На stock Android 12 без root работают Termux 0.118.3 и Termux:Boot 0.8.1.
- В Ubuntu 26.04 PRoot установлен Home Assistant Core 2026.10.1; локальный
  интерфейс доступен на порту `8123`, onboarding ещё не завершён.
- Стандартный Docker на штатном ядре признан непригодным.
- Android-прототип цветного голосового экрана собран и устанавливается
  воспроизводимым скриптом без Gradle.
- Экспериментальное постоянное прослушивание через системный Google
  `SpeechRecognizer` отключено: каждая новая recognition-сессия издавала звук.
- На телефоне установлен прототип `0.5.0`: openWakeWord ждёт «Помогатор», затем
  Vosk распознаёт команду цвета в шестисекундном окне foreground-службы.
- В ветке `feature/vosk-local-wakeword` обучена ONNX-модель «Помогатор»;
  её техническая проверка и сквозной Android self-test пройдены. Локально
  дообучен персональный кандидат «Эй, Помогатор»; он ещё не установлен.
  Test пройден на принятых фразах; дальше — уточнение двух исключений
  и независимая длительная проверка ложных срабатываний.

### «Помогатор»: от обхода словаря к своей модели

Vosk слышал выдуманное слово как «помогать», поэтому обучили отдельный
openWakeWord-детектор на русских Piper-голосах. Colab потребовал исправлений
PyArrow, Git LFS, загрузки AudioSet, TorchAudio и ONNX-экспорта. Исправления
собраны в повторяемый pipeline с журналами и checkpoint перед экспортом.
ONNX встроен перед Vosk: один микрофон, ожидание обращения, шесть секунд
на команду. Сквозной Android self-test совпадает с Python; качество на
реальном голосе ещё проверяем.
[Notebook, модель и детали](training/pomogator/README.md).

### «Эй, Помогатор»: свой голос вместо только синтетики

Синтетический детектор работал нестабильно на реальном произношении. Записали
отдельные train, validation, test и отрицательную речь; вручную приняли 40
обучающих и 10 проверочных фраз. Локально дообучили классификатор с аугментацией,
не отправляя голос в облако. Первый вариант ошибался на отрицательной речи;
добавили обрезки обучающих фраз как negatives. На validation получили 10/10
вместо 8/10, без ложных событий за минуту проверки. Порог 0.65 зафиксирован
до test, на телефоне пока исходная модель. Это эксперимент,
а не доказанная надёжность.
[Протокол и воспроизведение](training/pomogator/README.md).

Отдельный test затем дал 13/13 принятых фраз у обеих моделей: прирост обнаружений
не подтверждён. Два отклонённых фрагмента тоже вызвали срабатывания; требуется
уточнить их содержимое, чтобы отличить склейку фраз от ложного триггера.

## Цепочка решений

| Этап | Что проверили или сделали | Проблема / результат | Почему перешли дальше |
|---|---|---|---|
| 1. Диагностика телефона | ADB, модель, Android, boot state, ядро, namespaces, cgroups, файловые системы | `LM-V510N`, Android 12, Snapdragon 855; bootloader уже unlocked, Verified Boot `orange`, root отсутствует | Сначала зафиксировали исходное состояние и исключили действия вслепую |
| 2. Docker на Android | Требования Docker к namespaces, cgroups и OverlayFS | В ядре нет необходимого набора PID/IPC/user namespaces, контроллеров `devices`/`pids`/`freezer` и OverlayFS | Root/Magisk не добавит отсутствующие функции ядра; Docker потребовал бы кастомного ядра |
| 3. Root + chroot | Возможность получить более быстрый Linux userspace | Технически возможен, но требует Magisk/изменения boot и всё равно не даёт Docker | Для первого POC риск bootloop не оправдан; оставили как отдельный будущий эксперимент |
| 4. Нативный Linux | postmarketOS/mainline, UEFI и community-порты `mh2lm` | Есть исследовательские наработки, но нет подтверждённой готовой платформы для точного `LM-V510N` со всем серверно-критичным железом | Нужен отдельный porting-проект; для домашнего сервера путь слишком хрупкий |
| 5. Termux + PRoot | Обратимый Linux userspace без root | Подход работает, но это не контейнерная изоляция и нет systemd/cgroups | Это наименее инвазивный способ проверить полезность телефона как сервера |
| 6. Выбор Ubuntu | Сначала рассматривался Debian Bookworm | Актуальному Home Assistant потребовался Python `>=3.14.2`; выбранная Debian-база его не давала | Перешли на Ubuntu 26.04 ARM64, где нужный Python доступен |
| 7. Home Assistant Core | Установка в Python venv внутри PRoot | Home Assistant Core 2026.10.1 запускается и доступен в LAN; метод не является официально поддерживаемым HA Container/OS | Сначала проверяем функции и устойчивость, затем решаем, достоин ли телефон роли постоянного сервера |
| 8. Docker против PRoot | Повторно оценили надёжность и сопровождение | PRoot проще запустить, но Android может выгружать процессы, а обновления Python-зависимостей способны ломаться | Для production разумнее mini PC/ноутбук; телефон остаётся измеримым POC и edge-узлом |
| 9. Возможности Snapdragon | NNAPI HAL, Vulkan, OpenCL, DSP/HTA и vendor libraries | Ускорители доступны Android-приложениям, но не прозрачно Ubuntu/glibc внутри PRoot | Тяжёлые ML-задачи логичнее выполнять Android APK-сервисом и отдавать результат Home Assistant локально |
| 10. Голосовой экран 0.1 | Кнопка → системное распознавание ru-RU → смена цвета → TTS | Минимальная цепочка APK/микрофон/распознавание/экран заработала без root | Перешли к hands-free триггеру «Помогатор» |
| 11. Бескнопочный режим 0.2 | Последовательные сессии `SpeechRecognizer` в открытой Activity | Работает только пока Activity видима; это не настоящий hotword | Вынесли распознавание в microphone foreground-service |
| 12. Фоновый режим 0.3 | Foreground-service, постоянное уведомление, микрофон после сворачивания | Android подтвердил работающий фоновый микрофон, но телефон постоянно издавал уведомительный/системный звук | Сначала сделали полностью беззвучный notification channel, чтобы отделить источники звука |
| 13. Проверка звука 0.3.1 | Новый channel имел `sound=null`, без vibration/light и с only-alert-once | Звук продолжился: его создаёт начало/окончание циклических Google recognition-сессий, а не наше уведомление | Циклический `SpeechRecognizer` признан непригодным; глобально глушить звуки Android не стали |
| 14. Безопасная остановка 0.3.2 | Force-stop POC и сборка без автозапуска фоновой службы | Процесс/служба отсутствуют, AppOps не показывает активный микрофон | Переходим к непрерывному локальному `AudioRecord` + offline wake-word/ASR |
| 15. Android 17 | GSI, LineageOS и community-ROM для `mh2lm` | Android 17 существует, но GSI не является безопасной прошивкой для LG; подтверждённого Android 17 ROM для `LM-V510N` нет | Новая ОС не нужна для локального голоса и добавляет риск потери vendor DSP, модема, IMS и серверного окружения |
| 16. Vosk или Whisper | Сравнили потоковое offline ASR и более точное распознавание свободной речи | Vosk легче и работает потоком; Whisper тяжелее и не является wake-word движком | Сначала Vosk с ограниченным русским словарём, позже гибрид Vosk → Whisper → Home Assistant |

Текущая целевая схема:

```text
Android 12
├─ Termux + Ubuntu PRoot
│  └─ Home Assistant Core :8123
└─ Android foreground-service
   ├─ AudioRecord
   ├─ openWakeWord: ожидание обращения
   ├─ Vosk: короткие команды после триггера
   ├─ позднее Whisper: свободная речь после триггера
   └─ локальный API / Home Assistant action
```

## Почему сейчас не Docker

Проблема не в отсутствии APK «Docker» и не в выбранном Linux-дистрибутиве.
Docker daemon использует функции ядра, которых в stock LG kernel нет. Magisk
выдаёт привилегии, но не добавляет namespaces, cgroup controllers или
OverlayFS. Рабочий Docker означал бы сборку и прошивку кастомного ядра, а также
сопровождение сети, storage driver и Android/vendor-совместимости.

PRoot не притворяется Docker: он даёт Ubuntu userspace поверх того же Android-
ядра. Это медленнее и менее надёжно, зато обратимо и достаточно для POC.

## Почему Vosk раньше Whisper

Для команд нужен потоковый и относительно лёгкий движок. Vosk
работает offline с русской small-моделью и ограниченным словарём:
цвета и несколько команд. Для выдуманного обращения в итоге понадобился
отдельный openWakeWord-детектор. Whisper лучше понимает произвольные
фразы, но требует сегментации записи, больше CPU/RAM и не подходит как
постоянный детектор ключевого слова.

Планируемый гибрид:

```text
openWakeWord постоянно ждёт обращение
              ↓
Vosk распознаёт короткие команды
              ↓
сложную фразу передаёт Whisper
              ↓
намерение отправляется в Home Assistant
```

## Воспроизведение

### Подготовка Android/Termux

Основные Windows-сценарии находятся в [`scripts/`](scripts/README.md), а
сценарии, выполняемые внутри телефона, — в [`phone/`](phone/).

Последовательность установки серверного POC отражена в именах:

```text
phone/01-termux-bootstrap.sh
phone/02-install-ubuntu.sh
phone/03-ubuntu-install-home-assistant.sh
phone/04-start-home-assistant.sh
phone/05-stop-home-assistant.sh
```

Сценарии сохраняют вывод в `~/setup-logs/` на телефоне; экспортированные логи
лежат в [`logs/phone/`](logs/phone/).

### Сборка Android-прототипа

Требуются OpenJDK и Android SDK platform/build-tools 34.0.0. Из корня проекта:

```powershell
.\scripts\build-voice-color-station.ps1
```

Скрипт выполняет `aapt2 → javac/jar → d8 → zipalign → apksigner`. APK появляется
локально в `android/voice-color-station/artifacts/` и намеренно не хранится в
Git. Установка на авторизованный ADB-телефон:

```powershell
.\scripts\install-voice-color-station.ps1
```

Подробнее: [`android/voice-color-station/README.md`](android/voice-color-station/README.md).

## Границы эксперимента

Без отдельного решения и полного плана восстановления не выполняются прошивка
разделов, factory reset, установка Magisk, модификация boot/kernel и переход на
custom ROM. Этот репозиторий — воспроизводимый исследовательский POC, а не
утверждение, что телефон уже является production-сервером.
