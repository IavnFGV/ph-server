# Wake-word «Помогатор»

Цель — получить отдельную акустическую ONNX-модель, которая слышит именно
«Помогатор». После срабатывания команду по-прежнему распознаёт Vosk.

Следующий эксперимент — персональная фраза **«Эй, Помогатор»**:
[пошаговая запись и разделение данных](RECORDING_GUIDE.md).

`inspect_personal_recording.py` проверяет целостное декодирование и уровни
звука, сохраняет PCM-копию и private JSON-отчёт. Опциональный Vosk даёт
подсказки word timestamps, которые не считаются подтверждённой разметкой.

`prepare_personal_candidates.py` выделяет кандидаты по паузам, но не назначает
автоматически positive labels. `review_personal_recordings.py` поднимает
localhost-страницу для прослушивания только train/validation и сохраняет
пользовательские решения в private JSON. Принимать следует ровно одну полную
фразу «Эй, Помогатор»; обрезки, несколько повторов и сомнительные клипы
отбрасываются. Test и оригинальные длинные записи сервер не публикует.

После review доступно локальное CPU-дообучение, без загрузки голоса в Colab:

```powershell
.\scripts\train-personal-wakeword.ps1 -Stage prepare -RunName personal-v2 -HardNegatives 30 -InstallDependencies
.\scripts\train-personal-wakeword.ps1 -Stage fit -RunName personal-v2
```

`prepare` создаёт новый private run: 30 вариантов на каждую принятую train-фразу,
замороженные ONNX-признаки и неизменённый validation stream. Negative заранее
делится по времени: 0–132 с для обучения, 136 с–конец для проверки. Сегменты
из одной отрицательной записи не являются полностью независимыми условиями.
`fit` дообучает только head из старого checkpoint, сохраняет новый checkpoint
до ONNX-экспорта и сравнивает с исходной моделью на validation при пороге 0.5.
Test не читается. ONNX и checkpoint персональной модели остаются в `private/`;
в Git идут код, протокол и агрегированные результаты.

Для повторного эксперимента задайте новое `RunName`: `prepare` не перезаписывает
существующий набор. `fit` сохраняет результаты в этот run, поэтому для сохранения
разных запусков обучения используйте разные run-каталоги.

### Персональный эксперимент, 16 октября 2026

После ручной проверки принято 40 train и 10 validation фраз. Из train созданы
1200 positive вариантов. Первый запуск дал 10/10, но ложное срабатывание на
negative holdout. Во второй добавлены 1200 обрезков train-фраз как отрицательные
примеры (всего 3760 negatives). Выбран checkpoint шага 600 по validation:
сначала минимум ложных событий, затем максимум обнаружений, затем максимальный
зазор между худшим positive и худшим negative. Порог 0.65 зафиксирован до test.

| Модель | Обнаружения, validation | Ложные события, ~60 с negative |
|---|---|---|
| Исходная, порог 0.5 | 8/10 | 0 |
| Персональная v2, порог 0.65 | 10/10 | 0 |

Это выбор по validation, не финальная оценка: один голос и минута отрицательной
речи не доказывают надёжность. На момент выбора test ещё не использовался;
последующие test и установка описаны ниже.
Локальный результат: `private/runs/personal-v2/hey-pomogator-personal.onnx`,

### Отдельная проверка test

После фиксации модели/порога нарезка поддерживает `--split test` только вместе
с `--frozen-report private/runs/personal-v2/training-report.json` (пути от этой
папки). SHA-256 ONNX проверяется до чтения test, hash и threshold сохраняются
в test manifest. Это разметка полноты фразы, без предсказаний детектора.

```powershell
python training/pomogator/review_personal_recordings.py --test training/pomogator/private/candidates/test-v1 --decisions training/pomogator/private/test-review-decisions.json
```

Команда из корня открывает сервер на `http://127.0.0.1:8766/`. Обрабатывается
только test, без train/validation. Неполные/сомнительные фразы отмечаются отдельно;
если склеились несколько полных повторов, нужно уточнить границы, а не молча
исключить их. При оценке следует указать покрытие исходной записи/исключения.
Test labels не добавляются в train; параметры после просмотра test не подбираются.

`evaluate_personal_test.py --run training/pomogator/private/runs/personal-v2
--output training/pomogator/private/runs/personal-v2/held-out-test-report.json`
проверяет frozen hashes и полноту review, затем сравнивает ONNX на непрерывном
test stream. Существующий итог не перезаписывает. Python dependencies те же,
что для локального обучения. Окно оценки ограничено началом следующего
кандидата; rejected не считаются negative ground truth.

Результат 16 октября: принято 13 из 15 кандидатов, оба классификатора обнаружили
13/13 (personal threshold 0.65, generic 0.5). Преимущество по числу обнаружений
на test не показано. Исключены 004 и 015 (суммарно 9.65 с speech intervals);
обе модели активировались и там. Пользователь уточнил: в этих фрагментах
несколько полных обращений без нормальной паузы, а не посторонняя речь.
Это не false alarms; число и индивидуальные границы повторов не подтверждены,
поэтому дополнительные hits не приписываем. Это positive-window метрика, не симуляция Android
command window, не полнота всех произнесений и не измерение ложных событий/час.

После test personal-v2 установлен на LG в APK 0.6.0: один AudioRecord, прежнее
шестисекундное окно Vosk, порог 0.65. `android-profiles.json` закрепляет пути,
SHA-256 и synthetic references для generic/personal. Встроенная hash-проверка,
self-test и READY personal-v2 подтверждены на устройстве. Голосовая проверка
цветов выполнена пользователем: он сообщил о заметном улучшении и разрешил
merge. Количественный длительный negative/soak-test ещё не завершён.

## Почему не достаточно официального quick-start

Официальный Colab генерирует речь английским LibriTTS и просит убрать Unicode.
Русское слово в это поле вводить нельзя: звук получится неверным. Этот вариант
использует четыре русских Piper-голоса (`denis`, `dmitri`, `irina`, `ruslan`),
разные темпы и вариативность произношения, затем приводит WAV к 16 кГц.

## Запуск

1. Открыть `Pomogator_openWakeWord.ipynb` в Google Colab.
2. Включить GPU: **Среда выполнения → Сменить среду выполнения → T4 GPU**.
3. Выполнить ячейки по порядку. Первый POC: 1000 train + 500 test примеров.
4. Скачать `pomogator.onnx`, checkpoint, два stage-лога и
   `training-report.txt`.
5. Проверить модель на реальных записях до включения постоянного прослушивания.

Рабочие данные занимают десятки гигабайт: только общий набор отрицательных
признаков — около 17,28 ГБ. Данные официального notebook имеют смешанные
лицензии, поэтому результат считаем только личным некоммерческим POC.

## Что проверять

- 20–50 настоящих произнесений с разных расстояний;
- тишину, телевизор и обычную русскую речь минимум несколько часов;
- похожие слова из `NEGATIVE_PHRASES`;
- false reject и false activation при нескольких порогах.

Порог и интеграцию в Android выбираем только после этих измерений.

## Исправления для актуального Colab

`colab_pipeline.py` закрепляет ревизии датасетов, проверяет SHA-256 AudioSet,
ставит совместимый PyArrow, загружает Git LFS до чтения RIR, исправляет удаление
`torchaudio.info`, включает legacy ONNX exporter и сохраняет checkpoint до
экспорта. Все compatibility patches fail-fast: при изменении upstream они
останавливаются вместо тихого изменения неизвестного кода.
